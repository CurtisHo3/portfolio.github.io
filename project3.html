Access Management System for Toronto Paramedic Services

Course: APS112 | Winter 2025

Project Overview

Designed a Role-Based Access Control (RBAC) framework for Toronto Paramedic Services to streamline employee access management across 1,800+ personnel and 45+ stations. The solution replaces manual processes with an automated system that ensures security compliance and reduces processing time from weeks to under 2 days.

Systems Design RBAC Process Engineering Healthcare IT

The Challenge

Toronto Paramedic Services (TPS) lacked a systematic approach to manage employee access permissions across email, software applications, virtual files, and physical key-fob systems. Department managers manually tracked and updated permissions, introducing:

  • Delays: Access changes took several weeks to process
  • Security Risks: No centralized audit log or oversight
  • Inefficiency: Manual processes across 45+ stations
  • Compliance Issues: Difficulty meeting PHIPA requirements for patient data protection

Our Solution: RBAC Matrix Framework

After evaluating three design alternatives using Pugh chart analysis, our team proposed a Role-Based Access Control (RBAC) matrix that defines permissions for each role and automates approval workflows.

Design Process

Our team followed a rigorous engineering design methodology:

1. Stakeholder Analysis

  • Conducted client meetings with Commander John McPhee (Systems & IT Governance)
  • Identified key stakeholders: City of Toronto, IT Division, patients, payroll, Toronto Public Health
  • Mapped legal constraints from PHIPA (Personal Health Information Protection Act)

2. Requirements Definition

  • Effectiveness: >92% task completion rate
  • Efficiency: Process changes in <2 days
  • Minimal Complexity: <5 manual steps
  • Maintainability: Quarterly maintenance only

3. Idea Generation & Selection

Generated 52 initial concepts using:

  • Morph charts and SCAMPER methodology
  • Reverse brainstorming to identify failure modes
  • Multi-voting to narrow to 12 viable options
  • Feasibility analysis reducing to 3 final candidates

Alternative Designs Considered

Design 1: RBAC Matrix (Selected)

Predefined access control matrix with automated permission changes based on role transitions. Supervisor approval via email triggers updates. Temporary assignments automatically expire on specified dates.

Why we chose this: Best balance of effectiveness, efficiency, and maintainability with minimal AI-related risks.

Design 2: Smart Dashboard with AI Anomaly Detection

Online interface with LLM-based risk scoring to flag suspicious access requests. Calculated urgency scores based on scheduled change dates.

Why we didn't choose this: Higher maintenance requirements and potential AI hallucination risks.

Design 3: Dual Validation with Graph Database

Graph database mapping user-permission relationships with dual approval (supervisor + LLM) for all changes.

Why we didn't choose this: Required 2+ manual inputs with potential escalation, less efficient than RBAC.

Final Design: Permission Change Process

RBAC Matrix

Automated workflow for processing employee access changes through the RBAC matrix

Key Features

  • Automated Role Mapping: Pre-defined matrix assigns permissions based on employee roles
  • Supervisor Approval Workflow: Email-based approval system for non-routine changes
  • Temporary Access Handling: Automatic expiration for acting assignments and training periods
  • Audit Logging: Complete compliance with PHIPA requirements for patient data protection
  • Multi-Station Support: Scalable framework across all 45+ TPS locations

Testing & Validation

Developed a Python prototype to validate the design against edge cases:

  • Onboarding: Adding roles from zero-permission state
  • Offboarding: Removing all access upon departure
  • Role Transitions: Modifying permissions during promotions/transfers
  • Acting Assignments: Temporary access with automatic expiry

Success Criteria: 100% task completion rate across all test scenarios (per client requirement)
